# Creator Engine (Universal Creator Engine)

Package: `jarvis/creator/`. Turns a natural-language request into a **statically verified, packaged scaffold project**.
It never executes generated code (Phase 6F stays BLOCKED).

## Pipeline

```
request -> plan (C1 CreatorOrchestrator + 6C requirements) -> select generator (spec_builder)
        -> new isolated workspace (C2) -> generate (C3/C4/C5/C6 composers & templates)
        -> smoke-test generation -> static tests (C7) -> debug loop (<=3 rounds) -> re-test
        -> static preview (C8) -> package ZIP (C9) -> per-project memory + audit (C10)
```

Each stage is dispatched through typed agent contracts (`TaskContract`/`TaskResult`, permission boundaries, timeouts)
and every action passes `SecurityGate`.

## Using it

* Typed command in Aliena (hooked into `handle_command`): `create a website called "Sunrise Bakery" with a menu and a contact form`,
  `build a FastAPI api to manage tasks and categories`, `make a pygame game`, `build a mobile app ...`, `create a python command line tool ...`.
  Follow-ups: `creator projects|status|files|report|preview|package [id]`; `confirm export <id|last> to <folder>` (this phrase is the approval).
* Python: `CreatorEngine(root).create(request)`; explicit control with `create(request, spec=..., composer_id=...)`.
* Orchestrator: `register_creator_agent(registry, engine)` adds agent `creator` (opt-in; default registries unchanged).
* Examples (generated by `scripts/generate_creator_examples.py`): `examples/creator/example-website`, `examples/creator/example-python-app`.

## Support levels (honest)

Every generator is a **scaffold**. Nothing is built, installed or run by Aliena. `IMPLEMENTED_GENERATORS` in `stacks.py` stays empty on purpose.
Desktop apps have no generator; requests for them return `unsupported`. The spec derived from free text is a keyword heuristic (flagged `heuristic_spec`).
